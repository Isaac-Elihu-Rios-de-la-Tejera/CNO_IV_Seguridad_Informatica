Laboratorio 01: SIMPLE CASE

Descripción técnica:

  • Procedimiento realizado: Durante el desarrollo de la actividad, se explotó una vulnerabilidad de Path Traversal (CWE-22) manipulando la petición HTTP GET que utiliza la aplicación para cargar imágenes de productos. Se interceptó el tráfico y se modificó el parámetro filename, inyectando un payload de salto de directorio (../../../../etc/passwd). Al reenviar la petición, el servidor procesó la ruta sin validación, permitiendo evadir el directorio raíz de la web y retornando el contenido del archivo sensible del sistema operativo Linux.
  • Herramientas utilizadas:
    • Burp Suite (Community Edition): Utilizado para la interceptación de la petición y el uso del módulo Repeater para manipular y reenviar el payload.
    • Navegador Web: Empleado para interactuar con la aplicación vulnerable y verificar el estado del laboratorio.
    • PortSwigger Web Security Academy: Plataforma que aloja el entorno seguro de pruebas.
  • Objetivos cumplidos:
    1. Identificar la vulnerabilidad de salto de directorio en la carga de archivos.
    2. Manipular con éxito la petición HTTP para evadir las restricciones de directorio
    3. Extraer y visualizar información sensible del servidor (archivo /etc/passwd).
    4. Resolver exitosamente el laboratorio, obteniendo la confirmación de "Lab Solved".

Laboratorio 02: TRAVERSAL SEQUENCES BLOCKED WITH ABSOLUTE PATH BYPASS

Descripción técnica:

  • Procedimiento realizado: En este laboratorio se explotó una vulnerabilidad de Path Traversal con el objetivo de leer el archivo sensible /etc/passwd evadiendo un filtro de seguridad que eliminaba secuencias de navegación (../) de forma no recursiva. Utilizando Burp Suite (a través de su navegador integrado y el módulo Repeater) en el entorno de PortSwigger Web Security Academy, se interceptó una petición HTTP GET legítima destinada a la carga de imágenes y se manipuló su parámetro filename con el payload ....//....//....//....//etc/passwd. Esta técnica anidada engañó al servidor, ya que al eliminar el filtro la secuencia interna, la cadena colapsó en una travesía de directorios efectiva. De esta manera, se cumplieron exitosamente los objetivos de identificar la vulnerabilidad, evadir los controles de seguridad, lograr la lectura de archivos fuera del directorio web raíz y resolver el laboratorio confirmando el acceso no autorizado.
  • Herramientas utilizadas:
    • Burp Suite (Community Edition): Utilizada como proxy de intercepción (Burp Proxy) para el análisis de tráfico, y como entorno de pruebas (Burp Repeater) para la manipulación y envío de los payloads maliciosos.
    • Navegador Integrado de Burp (Chromium): Utilizado para la navegación segura y aislada dentro del entorno del laboratorio de PortSwigger.
    • Plataforma PortSwigger Web Security Academy: Entorno virtualizado que aloja la aplicación vulnerable.
  • Objetivos cumplidos:
    1. Identificación de la vulnerabilidad: Se confirmó la presencia de un Path Traversal en el parámetro de carga de archivos.
    2. Evasión de controles de seguridad: Se logró burlar exitosamente el filtro no recursivo implementado por el servidor.
    3. Lectura de archivos locales (LFI): Se obtuvo acceso de lectura no autorizado al archivo de cuentas del sistema (/etc/passwd), demostrando el impacto crítico de la vulnerabilidad.
    4. Resolución del laboratorio: La plataforma validó la explotación exitosa del entorno, marcando el laboratorio como "Solved" (Resuelto).

Laboratorio 04: TRAVERSAL SEQUENCES STRIPPED WITH SUPERFLUOUS URL-DECODE

Descripción técnica:

  • Procedimiento realizado: En este laboratorio se explotó una vulnerabilidad de Path Traversal (salto de ruta) en una aplicación web, cuyo objetivo era acceder a archivos sensibles del sistema operativo fuera del directorio raíz del servidor. La aplicación contaba con un filtro de seguridad que intentaba bloquear los ataques eliminando las secuencias de salto de directorio (../), sin embargo, cometía el error de aplicar este filtro antes de decodificar la URL. Para evadir esta protección, se interceptó la petición de carga de una imagen y se manipuló el parámetro filename utilizando una doble codificación URL (..%252f..%252f..%252fetc%252fpasswd). Al enviar el payload, el servidor no reconoció las secuencias maliciosas en la primera revisión, pero al decodificar la URL internamente, se reconstruyó la ruta ../ permitiendo el salto de directorios y la lectura exitosa del archivo de usuarios del sistema (/etc/passwd), demostrando así la falla en el orden de validación de las entradas del servidor.
  • Herramientas utilizadas:
    • Burp Suite (Community Edition): Utilizada como proxy de intercepción (Burp Proxy) para el análisis de tráfico, y como entorno de pruebas (Burp Repeater) para la manipulación y envío de los payloads maliciosos.
    • Navegador Integrado de Burp (Chromium): Utilizado para la navegación segura y aislada dentro del entorno del laboratorio de PortSwigger.
    • Plataforma PortSwigger Web Security Academy: Entorno virtualizado que aloja la aplicación vulnerable.
  • Objetivos cumplidos:
    1. Identificación de una vulnerabilidad de Path Traversal / Local File Inclusion (LFI).
    2. Evasión exitosa de un filtro de seguridad mediante la técnica de doble codificación URL (Superfluous URL-decode).
    3. Extracción y lectura no autorizada de un archivo crítico del sistema operativo Linux (/etc/passwd).
    4. Resolución completa del laboratorio, obteniendo la confirmación de "Lab Solved" en la plataforma.
