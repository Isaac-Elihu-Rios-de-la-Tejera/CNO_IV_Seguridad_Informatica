1. Nombre del laboratorio

File path traversal, traversal sequences blocked with absolute path bypass — PortSwigger Web Security Academy.

2. Nivel

Apprentice (Aprendiz).

3. Tipo de explotación

Path Traversal (Directory Traversal) mediante evasión de filtros utilizando rutas absolutas (Absolute Path Bypass).

4. Objetivo del laboratorio

Explotar una vulnerabilidad de Path Traversal en una aplicación web que utiliza el parámetro filename para cargar imágenes de productos.

Aunque la aplicación implementa mecanismos de seguridad para bloquear secuencias de retroceso de directorios (../), permite utilizar rutas absolutas sin realizar una validación adecuada.

El objetivo principal es aprovechar esta debilidad para acceder al archivo /etc/passwd del servidor Linux y recuperar información relacionada con las cuentas de usuario del sistema.

5. Explicación técnica de la vulnerabilidad

La vulnerabilidad Path Traversal ocurre cuando una aplicación web permite manipular rutas de archivos proporcionadas por el usuario, facilitando el acceso a recursos ubicados fuera de los directorios autorizados.

En este laboratorio, la aplicación utiliza el parámetro filename dentro de una petición HTTP GET para recuperar imágenes almacenadas en el servidor. 

GET /image?filename=11.jpg

Aunque existe un mecanismo que bloquea secuencias como ../, la aplicación no restringe correctamente el uso de rutas absolutas.

Una ruta absoluta comienza con el carácter / y permite especificar directamente la ubicación de un archivo desde la raíz del sistema Linux. 

/etc/passwd

Al procesar este tipo de rutas sin comprobar que pertenezcan al directorio autorizado, la aplicación puede abrir archivos sensibles del sistema, como /etc/passwd, en lugar de las imágenes solicitadas.

6. Procedimiento paso a paso

  1. Se ingresó al laboratorio de PortSwigger Web Security Academy y se verificó que su estado inicial fuera "Not solved".
  2. Se abrió la tienda virtual del laboratorio y se seleccionó un producto para generar una petición HTTP relacionada con la carga de una imagen.
  3. Mediante Burp Suite, se identificó la petición correspondiente a una imagen del producto. 
    GET /image?filename=11.jpg
  4. La petición se envió a la herramienta Repeater para analizar y modificar su contenido.
  5. Dentro de Repeater, se reemplazó el valor original del parámetro filename por la ruta absoluta /etc/passwd. 
    GET /image?filename=/etc/passwd
  6. Se presionó el botón Send para enviar la petición modificada al servidor.
  7. El servidor respondió con el código HTTP 200 OK, mostrando el contenido del archivo /etc/passwd, incluyendo registros de usuarios como root y daemon.
  8. Finalmente, se regresó al navegador y se verificó que el laboratorio había cambiado su estado a "Solved", confirmando que la vulnerabilidad fue explotada exitosamente.

8. Explicación del payload

El payload utilizado fue:

filename=/etc/passwd

Funcionamiento

  • filename: Es el parámetro utilizado por la aplicación para identificar el archivo que debe recuperar del servidor.
  • /: Representa la raíz del sistema de archivos Linux e indica que se está utilizando una ruta absoluta.
  • /etc/: Es un directorio del sistema Linux que contiene archivos de configuración.
  • passwd: Es el archivo que almacena información sobre las cuentas de usuario del sistema.

A diferencia de otros ataques de Path Traversal, en este laboratorio no fue necesario utilizar secuencias de retroceso como ../.

La explotación fue posible porque la aplicación bloqueaba estas secuencias, pero no verificaba adecuadamente las rutas absolutas.

Como resultado, el servidor procesó directamente la ruta /etc/passwd y devolvió su contenido mediante una respuesta HTTP, en lugar de limitar el acceso al directorio de imágenes autorizado.

9. Mitigación recomendada

Para prevenir vulnerabilidades de Path Traversal mediante rutas absolutas, se recomiendan las siguientes medidas:

  1. Validación de entradas: Verificar que los parámetros proporcionados por el usuario no contengan rutas absolutas ni referencias a directorios no autorizados.
  2. Listas de archivos permitidos: Restringir el acceso únicamente a archivos previamente autorizados, utilizando identificadores internos en lugar de rutas proporcionadas directamente por el usuario.
  3. Validación de rutas canónicas: Resolver la ruta real del archivo solicitado y comprobar que permanezca dentro del directorio base permitido, evitando accesos mediante rutas absolutas o secuencias de retroceso.
  4. Control de permisos: Aplicar el principio de mínimo privilegio para limitar los archivos a los que puede acceder el proceso del servidor web.
  5. Protección de archivos sensibles: Configurar adecuadamente los permisos y controles de acceso para impedir que la aplicación pueda consultar información del sistema que no necesita para su funcionamiento.
