3. OBJETIVO DE LA ACTIVIDAD[cite: 2]

Objetivo general[cite: 2]

Implementar y analizar, dentro de un entorno de laboratorio controlado, una simulación de ingeniería social utilizando Social-Engineer Toolkit (SET) y una página web ficticia diseñada específicamente para la práctica, con la finalidad de comprender el funcionamiento de una técnica de captura de información y reconocer los elementos que pueden permitir identificar un intento de phishing.[cite: 2]

Objetivos específicos[cite: 2]

  • Configurar un escenario básico de ingeniería social utilizando Social-Engineer Toolkit (SET).[cite: 2]
  • Implementar una página web ficticia mediante el módulo Credential Harvester.[cite: 2]
  • Analizar el proceso mediante el cual la información introducida en un formulario web es transmitida y registrada por un servidor.[cite: 2]
  • Identificar indicadores técnicos y visuales que permitan reconocer una página potencialmente fraudulenta.[cite: 2]
  • Proponer controles de seguridad orientados a prevenir o reducir el impacto de ataques de phishing.[cite: 2]

4. DESCRIPCIÓN DEL ESCENARIO[cite: 2]

La actividad plantea un escenario en el que una organización recibe reportes de empleados relacionados con un supuesto mensaje de actualización de credenciales.[cite: 2]

El mensaje dirige a la persona usuaria hacia un portal que aparenta pertenecer a una organización legítima.[cite: 2] La página contiene elementos que buscan generar confianza, como un nombre institucional, campos de usuario y contraseña y un mensaje relacionado con la expiración de una sesión.[cite: 2] Sin embargo, el portal utilizado en la simulación no pertenece realmente a la organización.[cite: 2]

Para realizar la práctica se construyó una página web ficticia denominada ShopTrend, diseñada específicamente para el laboratorio.[cite: 2] La página contiene un portal de acceso con los elementos solicitados:[cite: 2]

  • Nombre del sistema.[cite: 2]
  • Campo de usuario.[cite: 2]
  • Campo de contraseña.[cite: 2]
  • Botón de ingreso.[cite: 2]
  • Mensaje indicando que la sesión ha expirado.[cite: 2]
[Espacio reservado para la Imagen: Máquina virtual mostrando la configuración de red y la página web ShopTrend]

La actividad se desarrolló exclusivamente dentro de un entorno virtual controlado, utilizando una máquina con Kali Linux y otra con Windows 10.[cite: 2] No se utilizaron páginas pertenecientes a servicios reales ni credenciales personales.[cite: 2]

7. EXPLICACIÓN DEL FLUJO DE CAPTURA DE INFORMACIÓN[cite: 2]

7.1. ¿Qué es un Credential Harvester?[cite: 2]

Un Credential Harvester es una técnica utilizada para capturar información introducida por una persona usuaria en un formulario web.[cite: 2] Dentro de una campaña de phishing, puede utilizarse como mecanismo para obtener información de autenticación cuando una persona introduce sus datos en una página fraudulenta.[cite: 2] Su función dentro de una campaña de phishing consiste en aprovechar una página que aparenta ser legítima para inducir a la persona usuaria a proporcionar información, generalmente mediante campos de autenticación.[cite: 2]

La actividad busca precisamente analizar esta situación mediante una página ficticia y un entorno controlado.[cite: 2]

7.2. Flujo realizado en el laboratorio[cite: 2]

El flujo de la práctica fue el siguiente:[cite: 2]

  • En primer lugar, Windows 10 accedió mediante el navegador a la dirección correspondiente al servidor local de Kali Linux.[cite: 2]
  • Posteriormente se mostró la página web ficticia desarrollada para la actividad. La interfaz contenía el formulario de autenticación.[cite: 2]
  • Al introducir los datos de prueba y enviar el formulario, se generó una solicitud hacia el servidor que ejecutaba SET.[cite: 2]
  • Credential Harvester procesó dicha interacción y permitió observar la información recibida en la terminal de Kali Linux.[cite: 2]

La práctica permitió comprobar que el elemento más importante del proceso no es únicamente la apariencia de la página, sino también el comportamiento que ocurre detrás del formulario.[cite: 2]

7.3. Indicadores que permitirían detectar una página fraudulenta[cite: 2]

A partir de la simulación se pueden identificar diferentes indicadores que una persona usuaria debería revisar antes de proporcionar información.[cite: 2]

  • Dirección del sitio: La dirección del navegador debe revisarse cuidadosamente.[cite: 2] Una página visualmente idéntica a una organización legítima puede utilizar una dirección diferente.[cite: 2]
  • Solicitudes inesperadas: Un mensaje que indique que una sesión expiró y solicite volver a ingresar las credenciales puede utilizarse para generar urgencia.[cite: 2]
  • Certificado y conexión: El uso de HTTPS es importante para proteger la comunicación, pero por sí solo no garantiza que un sitio sea legítimo.[cite: 2] El material de la asignatura señala específicamente que HTTPS no autentica que un sitio sea oficial.[cite: 2]
  • Apariencia visual: Elementos como logotipos, colores, formularios y mensajes pueden utilizarse para generar confianza.[cite: 2] Por ello, la apariencia de un sitio no debe considerarse suficiente para comprobar su autenticidad.[cite: 2]
  • Solicitud de credenciales: Una solicitud inesperada de usuario y contraseña debe considerarse un indicador de riesgo y debe verificarse antes de introducir información.[cite: 2]

8. CONTROLES DE SEGURIDAD PROPUESTOS[cite: 2]

La simulación permite observar cómo una persona usuaria puede ser engañada mediante una página que visualmente parece legítima.[cite: 2] Por ello, es necesario combinar controles técnicos con medidas de concientización.[cite: 2]

8.1. Capacitación de usuarios[cite: 2]

Las organizaciones deben capacitar periódicamente a sus usuarios para reconocer mensajes sospechosos, páginas falsas y solicitudes inesperadas de credenciales.[cite: 2] La capacitación debe incluir ejemplos prácticos de phishing e ingeniería social.[cite: 2]

8.2. Verificación de la dirección web[cite: 2]

Antes de introducir información confidencial, la persona usuaria debe verificar cuidadosamente la dirección del sitio.[cite: 2] Una recomendación presentada en el material de la asignatura consiste en acceder directamente al espacio personal desde la URL conocida, en lugar de hacerlo mediante enlaces recibidos inesperadamente.[cite: 2]

8.3. Autenticación multifactor[cite: 2]

La autenticación multifactor agrega una capa adicional de protección.[cite: 2] De esta manera, incluso si una contraseña llegara a ser obtenida mediante phishing, el atacante tendría una dificultad adicional para acceder a la cuenta.[cite: 2]

8.4. Contraseñas únicas y seguras[cite: 2]

Las personas usuarias deben evitar reutilizar la misma contraseña en diferentes servicios.[cite: 2] El material de la asignatura recomienda utilizar contraseñas fuertes y diversificadas y evitar utilizar la misma contraseña para servicios diferentes.[cite: 2]

8.5. Actualización de sistemas y navegadores[cite: 2]

Los sistemas operativos y navegadores deben mantenerse actualizados para reducir la exposición a vulnerabilidades conocidas.[cite: 2] El material de la asignatura también recomienda mantener actualizados tanto el sistema operativo como el navegador web.[cite: 2]

8.6. Revisión periódica de cuentas[cite: 2]

Es recomendable revisar periódicamente las cuentas para detectar actividades inusuales o accesos que no hayan sido realizados por la persona propietaria.[cite: 2] Esta recomendación también forma parte del material de la asignatura.[cite: 2]

8.7. No confiar únicamente en la apariencia[cite: 2]

La simulación demuestra que una página puede presentar una apariencia convincente y aun así representar un riesgo.[cite: 2] Por ello, la revisión debe considerar elementos técnicos, dirección web, contexto del mensaje y comportamiento de la página, y no únicamente su diseño visual.[cite: 2]

9. CONCLUSIÓN[cite: 2]

La realización de esta actividad permitió comprender de manera práctica cómo funciona una simulación de ingeniería social mediante Social-Engineer Toolkit (SET) y una página web ficticia.[cite: 2] A través del laboratorio fue posible observar cómo la interacción con un formulario aparentemente legítimo puede provocar que la información introducida por el usuario sea recibida por el servidor.[cite: 2]

Además, la práctica permitió identificar algunos de los riesgos asociados al phishing, especialmente cuando una página utiliza elementos visuales y mensajes que buscan generar confianza o urgencia en el usuario.[cite: 2] Por ello, es importante verificar la dirección del sitio antes de introducir información y no confiar únicamente en la apariencia de una página.[cite: 2]

Finalmente, se pudo comprobar la importancia de combinar medidas técnicas, como la autenticación multifactor y el uso de contraseñas seguras, con la capacitación de los usuarios para reconocer posibles intentos de phishing.[cite: 2] De esta manera, es posible reducir la probabilidad de que este tipo de ataques tenga éxito.[cite: 2]
