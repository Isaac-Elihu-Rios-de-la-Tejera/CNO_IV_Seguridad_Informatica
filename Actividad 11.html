1. Nombre del laboratorio

File path traversal, validation of start of path

2. Nivel

Apprentice (Aprendiz)

3. Tipo de explotación

Path Traversal / Directory Traversal (Salto de directorios).

La explotación consiste en manipular una ruta controlada por el usuario mediante el parámetro filename, conservando el prefijo requerido por la aplicación pero agregando secuencias ../ para salir del directorio autorizado.

4. Objetivo del laboratorio

Explotar una vulnerabilidad de Path Traversal presente en el parámetro filename, utilizado por la aplicación para cargar imágenes desde el servidor.

El archivo objetivo es:

/etc/passwd

Aunque la aplicación comprueba que la ruta comience con: 

/var/www/images/

la validación es insuficiente porque permite introducir secuencias de recorrido de directorios como: 

../

5. Explicación técnica de la vulnerabilidad

La aplicación utiliza el parámetro filename para determinar qué archivo debe recuperar. Una solicitud legítima puede tener la siguiente forma: 

GET /image?filename=/var/www/images/34.jpg

El servidor comprueba que la ruta recibida comience con el directorio autorizado: 

/var/www/images/

Sin embargo, la aplicación no comprueba de forma segura la ubicación final del archivo después de resolver las secuencias de recorrido.

Un atacante puede enviar:

/var/www/images/../../../etc/passwd

La cadena sigue comenzando con el prefijo permitido, por lo que puede superar la validación inicial. Las secuencias ../ hacen que el sistema de archivos avance hacia directorios superiores.

/var/www/images/ Directorio inicial permitido
↓
../ → /var/www/ Primer retroceso
↓
../ → /var/ Segundo retroceso
↓
../ → / Tercer retroceso
↓
/etc/passwd Archivo final solicitado

La vulnerabilidad existe porque la aplicación valida únicamente el comienzo de la cadena, pero no comprueba correctamente la ruta canónica o normalizada resultante.

6. Procedimiento paso a paso

  1. Acceder al laboratorio de PortSwigger Web Security Academy.
  2. Iniciar Burp Suite y utilizar el navegador configurado con el proxy de Burp.
  3. Seleccionar un producto para generar una solicitud de carga de imagen.
  4. Localizar en Proxy → HTTP history una solicitud similar a: 
    GET /image?filename=/var/www/images/34.jpg
  5. Enviar la petición a Burp Repeater.
  6. Enviar primero la solicitud original para comprobar el comportamiento normal de la aplicación.
  7. Modificar el parámetro filename por: 
    /var/www/images/../../../etc/passwd
  8. Presionar Send para enviar la petición modificada.
  9. Comprobar que la respuesta contiene información correspondiente al archivo /etc/passwd.
  10. Regresar al navegador y verificar que el laboratorio cambia de Not solved a Solved.

8. Explicación del payload

El payload utilizado fue:

/var/www/images/../../../etc/passwd

Directorio requerido por la aplicación

/var/www/images/

Esta parte se conserva porque la aplicación comprueba que el valor de filename comience con dicho prefijo.

Secuencias de recorrido

../../../

Cada secuencia ../ indica al sistema de archivos que debe acceder al directorio padre.

Ruta inicial /var/www/images/
1.er ../ /var/www/
2.º ../ /var/
3.er ../ /

Archivo objetivo

etc/passwd

Por lo tanto, la ruta:

/var/www/images/../../../etc/passwd

se normaliza conceptualmente como:

/etc/passwd

9. Mitigación recomendada

  • Evitar recibir rutas completas desde el cliente: utilizar identificadores internos como id=34 y asociarlos en el servidor con archivos previamente definidos.
  • Aplicar listas blancas: permitir únicamente archivos o nombres expresamente autorizados.
  • Rechazar secuencias peligrosas: bloquear patrones como ../, ..\, / o \ cuando no sean necesarios.
  • Normalizar o canonicalizar la ruta: resolver primero la ubicación real del archivo antes de comprobar si está permitido.
  • Validar la ruta final: comprobar que la ruta normalizada siga perteneciendo al directorio autorizado /var/www/images/.
  • Aplicar el principio de menor privilegio: limitar los permisos del proceso del servidor web.
Conclusión de seguridad: validar únicamente el inicio de una ruta no garantiza que el archivo final pertenezca al directorio permitido. La aplicación debe comprobar la ubicación final después de normalizar la ruta completa.
